# 现场试用执行手册（10+ 人）

目标：让 10 名以上真实用户在现场或同一局域网内完成 3 个科研任务，留下可核对的使用事件、反馈、问卷与前后耗时对比，作为「使用效果」评分项的证据。

## 一、准备（组织者，约 10 分钟）

1. 启动应用并确认容器健康：

   ```bash
   docker compose up -d
   make seed          # 已有 demo 项目可跳过
   make trial N=12    # 创建 trial-01 ~ trial-12，每人独立项目与记忆空间
   ```

2. 查询本机局域网 IP（Windows）：

   ```bash
   ipconfig
   ```

   当前这台机器的 WLAN 地址为 `192.168.220.55`，试用入口即：

   ```
   http://192.168.220.55:8080/?u=U01
   ```

   其他设备能打开后，再开始约人。若打不开，先放行 Windows 防火墙 8080 端口（管理员 PowerShell，仅首次）：

   ```powershell
   New-NetFirewallRule -DisplayName "PaperLens 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
   ```

3. 为每位试用者分配一个编号 `U01`…`U12`，并在自己的记录表里只写编号，不写姓名/手机号。

4. 准备：纸笔或手机秒表、问卷链接（见 `questionnaire.md`）、本目录的 `timing.csv`。

## 二、每位试用者流程（约 20 分钟）

| 步骤 | 时间 | 做什么 | 检查点 |
| --- | --- | --- | --- |
| 1 | 2 分钟 | 用带 `?u=U0X` 的链接打开应用，确认右上角「试用者」是该编号，当前项目是「试用 U0X」 | 编号、项目都正确 |
| 2 | 3 分钟 | 不做任何指导，先完成**基线任务**（用平时习惯的搜索引擎/数据库/自己读摘要）并计时 | 记录 3 个基线耗时 |
| 3 | 3 分钟 | 在「长期记忆」页写入 1 条自己的偏好，例如「输出风格：结论先行，中文，保留英文术语」 | 刷新后记忆仍在 |
| 4 | 5 分钟 | 用 PaperLens 完成任务 A/B/C 并计时；任务 A 分别关/开记忆各跑一次 | 检索结果有片段和页码，综述有 `[P#]` |
| 5 | 3 分钟 | 对至少 3 条检索结果点「相关 / 不相关」 | 使用统计页出现反馈数 |
| 6 | 5 分钟 | 填写问卷，组织者截图「使用统计」页 | 问卷提交成功 |

> 不要替试用者操作，也不要提示答案；只解释按钮位置。任务完成即可停止计时，不要求做到完美。

## 三、三个任务

### 任务 A：找文献（找得准）

> 从 20 篇文献中找出 **2025 年及以后、与 LLM Agent 记忆或评测相关** 的论文，给出 3 篇标题，并说明依据。

- 基线：用 Google Scholar / arXiv / 平时工具检索，记录从读题到能报出 3 篇标题的分钟数。
- PaperLens：混合检索页输入问题，打开「年份 ≥ 2025」与关键词过滤，记录耗时。
- 记忆 A/B：同一问题先关闭记忆跑一次，再打开记忆跑一次，记录「本次召回的记忆」是否出现、结果或排序是否有变化。

### 任务 B：对比方法（比得快）

> 选 3 篇论文，对比它们的**问题、方法、数据/实验、结论、局限**。

- 基线：只读摘要和必要段落，手写或打字整理，记录耗时。
- PaperLens：勾选 3 篇 → 综述生成 → 生成对比，记录耗时；检查对比是否逐项对应、是否带引用。

### 任务 C：写综述初稿（写得成）

> 基于所选文献写一段 300–500 字的综述初稿，每个结论都要标注 `[P#]`，导出 Markdown。

- 基线：自己组织语言写初稿，记录耗时。
- PaperLens：输入综述问题 → 生成 → 检查无「越界引用」提示 → 点「导出 Markdown」，记录耗时。

## 四、计时规则

- 从试用者**读完题**开始，到能交出一个「自己认可可用」的结果为止，单位分钟，保留 0.5。
- 基线任务与 PaperLens 任务必须由同一人、同一天、同一设备完成。
- 不计入启动应用、等待页面加载超过 10 秒的时间；若发生卡顿，在 `notes` 里注明。
- 三个任务分别记录，不取平均；汇总时按任务算中位数与节省比例。

## 五、数据采集与导出

试用结束后：

```bash
make evidence
```

会额外生成：

- `evidence/usage/trial/trial_events.csv`：按试用者编号的检索/综述/反馈事件
- `evidence/usage/trial/trial_feedback.csv`：相关/不相关反馈
- `evidence/usage/trial/trial_summary.json`：每人事件数、检索数、综述数、反馈数、平均耗时

同时保存：

- `timing.csv` 填好的原始表
- 问卷平台导出的原始结果（CSV/Excel）与截图
- 「使用统计」页截图、`/api/dev/trial_summary` 返回截图
- 现场照片 1–2 张（不拍屏幕外的个人信息，发布前打码）

## 六、隐私与合规

- 应用内只使用 `U01`…`U12` 编号，不采集姓名、学号、手机号、邮箱。
- 问卷第一页写明用途与匿名原则，并设置「同意将匿名数据用于比赛材料」选项；不同意者不纳入统计。
- 发布问卷结果时删除自由文本中的可识别信息。
- 屏幕和录屏中不得出现真实 API Key；`.env` 不进入仓库。

## 七、常见问题

**Q：试用者打开链接后还是别人的项目？**
A：确认链接带 `?u=U0X`，且 `make trial` 已执行；仍不对时在顶部「当前项目」手动选择「试用 U0X」。

**Q：同一台电脑多人试用怎么办？**
A：每位试用者用不同浏览器或不同浏览器配置文件打开各自带 `?u=` 的链接；不要把同一个浏览器会话交给两个人。

**Q：局域网设备打不开？**
A：检查是否同一 Wi-Fi、Windows 防火墙是否放行 8080、手机是否开了 AP 隔离（访客网络常见）。

**Q：试用中发现 bug？**
A：记录编号、操作步骤、时间和截图，先不修；当天汇总后统一修复并复测，修复记录进入 `evidence/qoder/`。
